## 2. The Disproof of Construction 2
The failure of the initial implementation was not due to coding errors. We employed a rigorous, multi-stage verification process to rule out every possible implementation mistake or minor typographical error in the source text.

### Phase 1: Symbolic Sign Verification (Z3 Theorem Prover)
**Hypothesis:** The paper might have sign errors (e.g., $+/-$ typos) in the complex formula.
**Method:** We implemented the logic in the Z3 SMT solver, treating every single sign in the 20-block construction as a variable.
*   **Search Space:** $2^{20} \approx 1,000,000$ combinations.
*   **Result:** `UNSAT` (Unsatisfiable). 
*   **Conclusion:** No combination of signs exists that yields a valid code.

### Phase 2: Structural Verification
**Hypothesis:** The paper might have swapped sequence definitions (e.g., using $F$ instead of $G$, or $A$ instead of $B$) or index directions.
**Method:** We extended the Z3 model to allow arbitrary swapping of components within the blocks.
*   **Search Space:** Effectively infinite if brute forced; solved symbolically by Z3.
*   **Result:** `UNSAT`.
*   **Conclusion:** The mismatch is structural. The "blocks" generated by Turyn(3) and Golay(2) sequences fundamentally do not possess the orthogonality properties required to cancel each other out.

### Phase 3: Parameter Sensitivity Analysis
**Hypothesis:** Perhaps the specific case $(n=3, k=2)$ is a unique "unlucky" edge case where the theorem fails, but it works for other integers.
**Method:** We automated the search for valid Turyn/Golay sequences for smaller and larger parameters and tested the construction logic on them.
*   **Test Cases:**
    *   $n=2, k=1 \rightarrow$ `UNSAT`
    *   $n=3, k=1 \rightarrow$ `UNSAT`
    *   $n=4, k=1 \rightarrow$ `UNSAT`
    *   $n=5, k=1 \rightarrow$ `UNSAT`
*   **Conclusion:** The theorem fails consistently across all parameter scales. This suggests the published theorem statement contains a fundamental theoretical error.

### Phase 4: Heuristic Approximation (Simulated Annealing)
**Goal:** To find the "closest possible" invalid solution, in case a near-miss is useful.
**Method:** We used Simulated Annealing to search for an arbitrary permutation of the blocks that minimizes the non-periodic autocorrelation (NPAF).
**Result:** The best solution found had an "Energy" (sum of squared errors) of **2404**. A perfect code has Energy 0. The large residual error confirms that the components are highly incompatible.
